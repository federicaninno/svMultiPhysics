Internal_force / External_force outputs for struct equations
==============================================================

CONTEXT
-------

The user is solving an inverse problem: estimating a spatially-heterogeneous
Young's modulus field in a passively-inflated left ventricle from displacement
data. svMultiPhysics runs the forward problem; a separate code does the
inversion. To validate the forward solve and cross-check the inverse code,
the user wants to verify force/equilibrium balance directly from
svMultiPhysics output: at every free node, the internal (material/inertial)
resistance should equal the externally applied load; at constrained nodes,
the imbalance is the reaction force.

Today these two contributions are summed into a single combined residual
during Newton-Raphson assembly and used only to check convergence -- they are
never persisted separately. This plan adds two new per-node vector VTK
outputs, Internal_force and External_force, for phys_struct equations
only (matching the scope of the earlier Strain_energy output work on this
branch), computed by capturing the existing assembly terms into two parallel
"shadow" global arrays instead of only their sum.

Field definitions (agreed with user):
- Internal_force = stress-divergence term (integral of grad(N).P) PLUS
  inertia (rho*accel) PLUS damping -- i.e. everything currently folded into
  Nx*P and the inertia/damping part of `ud` in the element residual.
- External_force = true prescribed loads only -- domain body force
  (f_x/f_y/f_z props) + per-node prescribed body force field (com_mod.Bf)
  + prescribed boundary pressure/traction (plain and follower-load Neumann
  BCs).

This grouping (not a 3-way split) gives an EXACT equality,
Internal_force ~= External_force, at every free node once Newton's method
converges -- verified algebraically and against the code below -- because it
mirrors exactly how the residual is already built, just with the terms
partitioned differently instead of approximated.

Verified sign convention: in every place the residual is assembled for
phys_struct (sv_struct.cpp:601-701 volumetric; l_elas.cpp:29 plain
traction; sv_struct.cpp:65-66,162-164 follower pressure), stress/inertia/
damping terms are added to lR (lR += ...) and load terms are subtracted
(lR -= ...). So lR = Internal_local - External_local everywhere. This
means: External_local(i,a) = -lR(i,a) in the two boundary-only functions
(where lR starts at zero and only carries the load term).

Known limitation to document, not fix: Robin BCs, weak-Dirichlet penalty
BCs, and contact forces also affect the true residual for phys_struct but
are out of scope here (not body force or prescribed pressure/traction). At
any node touched by one of those, Internal - External will not read as
exactly 0 or the true reaction force. This is a documented caveat, not a bug.

WHY THIS IS SAFE / CORRECTLY SCOPED
------------------------------------
- Scoping to phys_struct is enforced independently in three places:
  construct_dsolid's own per-domain phys_struct check, the
  cPhys == phys_struct guards added in both eq_assem.cpp boundary functions
  (which are shared with other physics), and the eq.phys == phys_struct
  guards in Integrator.cpp. phys_ustruct/FSI/shell paths are untouched.
- Fint_g/Fext_g are populated by direct local-to-global scatter (bypassing
  eq.linear_algebra->assemble()'s backend-specific Dirichlet-elimination
  machinery entirely, same as the existing pSn/pSa prestress pattern), so
  they retain the raw, pre-elimination values -- meaning Internal - External
  correctly reads as the reaction force at Dirichlet-constrained nodes, not
  silently zero.
- The existing ud computation in struct_3d/struct_2d is left completely
  untouched (only new parallel udi/fext_gp locals are added); lR/lK and
  therefore the actual Newton solve are numerically unaffected by this
  change.
